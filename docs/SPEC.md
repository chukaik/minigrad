Question. Can I implement reverse-mode automatic differentiation correctly from scratch? How close does a plain NumPy implementation get to PyTorch, in accuracy and in speed on a laptop CPU?

What gets built
- A Tensor class wrapping a NumPy array. Each tensor records which operation created it and computes gradients backwards through the graph, using a topological sort.
- Operations:
  - add, subtract, multiply, negate and divide (with broadcasting);
  - matrix multiply, sum and mean (with axis and keepdims), reshape and transpose;
  - ReLU, exp and log;
  - a combined, numerically stable softmax cross-entropy loss.
- Network pieces: a Linear layer with He initialisation, a small MLP, and SGD with momentum.
- An MNIST loader in NumPy that downloads the original files once and caches them in data/, which is not committed.

Correctness checks
- Every operation's gradient is checked against central finite differences in float64. The relative error must be below 1e-6, including broadcasting cases.
- Gradients are compared with PyTorch on random inputs. PyTorch is only a development dependency, and these tests are skipped where it isn't installed, for example in CI.

Experiment
- Train a 784-128-10 network and a 784-256-128-10 network on MNIST: 10 epochs, batch size 64, learning rate 0.1, momentum 0.9, three random seeds each.
- Report test accuracy as mean and spread, and time per epoch (median of three runs).
- Compare with the identical network trained in PyTorch on the same laptop, with 1 thread and with the default thread count.
- Record the machine details: processor, RAM, and Python, NumPy and PyTorch versions.

Success criteria
- All tests pass locally and in GitHub Actions.
- The 784-128-10 network reaches at least 97% test accuracy. That is typical for this network; if it falls short, report the real number.
- Every number in the README can be regenerated by one script.

Out of scope: GPUs, convolutions, and second derivatives.

Deliverables
- The library, tests, and a training script.
- scripts/run_all.py, which regenerates every result.
- Result CSVs and three figures: loss curves, accuracy, and time per epoch.
- A README that derives each gradient, including the softmax cross-entropy simplification and how broadcasting is undone in the backward pass.

What the author must be able to explain
- Why reverse mode suits neural networks.
- Why the backward pass needs a topological order.
- How broadcasting changes a gradient.
- Why log-sum-exp keeps softmax stable.
- Why gradient checks use float64.
- Why a NumPy implementation is slower than PyTorch.

References
- Baydin et al., "Automatic Differentiation in Machine Learning: a Survey", JMLR 2018.
- Andrej Karpathy's micrograd, a well-known teaching project, acknowledged in the README as an inspiration.
